# Backend Current Status & API Documentation

This document describes the current development status of the backend for the UniVerse Platform. It provides a comprehensive list of successfully implemented features, architecture, and currently available API endpoints.

## 🏗️ Backend Architecture

- **Framework**: Fastify (Node.js/TypeScript)
- **Database ORM**: Prisma (PostgreSQL database)
- **Authentication**: Custom JWT (Access & Refresh tokens) + OTP based verification
- **Security**: Helmet, CORS, Rate Limiting integrated.
- **Error Handling**: Centralized error middleware (`errorHandler.ts`)
- **Role-Based Access Control (RBAC)**: Implemented in `rbac.ts` middleware.

## 🚀 Available API Modules & Endpoints

Base URL: `{baseUrl}/api` (e.g. `http://localhost:5000/api`)

### 1. 🔐 Auth Endpoints (`/api/auth`)
*Handles user registration, login, OTP verifications, and sessions.*
- `POST /api/auth/register` - Register a new account (teacher, security, parent).
- `POST /api/auth/verify-otp` - Verify the OTP to complete registration.
- `POST /api/auth/login` - Login with credentials (email & password).
- `POST /api/auth/resend-otp` - Request a new OTP.
- `POST /api/auth/forgot-password` - Request an OTP for a forgotten password.
- `POST /api/auth/reset-password` - Reset password using the provided OTP.
- `PUT  /api/auth/link-child` - Parent links a child via Student ID + OTP.
- `POST /api/auth/refresh` - Silently refresh JWT token.
- `POST /api/auth/logout` - Logout the current session.
- `POST /api/auth/logout-all` - Revoke all active sessions for the user.
- `PUT  /api/auth/fcm-token` - Update Firebase FCM token for push notifications.

### 2. 👤 User Management (`/api/users`)
*Handles user profiles, and administrative actions per role.*
- `GET  /api/users/me` - Get the current logged-in user profile.
- `PUT  /api/users/me` - Update profile data (name, avatar, etc.).
- `GET  /api/users/pending` - Fetch accounts pending approval/promotion (Admin).
- `PUT  /api/users/:id/promote` - Promote a pending account to a specific role like 'teacher' or 'security'.
- `PUT  /api/users/:id/suspend` - Suspend a user account.
- `PUT  /api/users/:id/unsuspend` - Lift a user account suspension.

### 3. 🏫 School Structure (`/api/school`)
*Handles grades, classes, and student records.*
- `POST /api/school/grades` - Create a new grade level.
- `GET  /api/school/grades` - Retrieve list of all grade levels.
- `POST /api/school/classes` - Create a new class.
- `GET  /api/school/classes` - Retrieve a list of all classes.
- `GET  /api/school/classes/mine` - Retrieve the classes assigned to the requesting teacher.
- `GET  /api/school/classes/:id/students` - Get the list of students in a specific class.
- `POST /api/school/students` - Register a new student record.
- `GET  /api/school/students` - List all students.

### 4. 🚪 Gate & Security (`/api/gate`)
*Handles student entries and exits via ID scans.*
- `POST /api/gate/scan` - Record a student gate entry or exit (via QR Code or manual entry).
- `GET  /api/gate/events` - Retrieve gate event logs.

### 5. 📅 Attendance (`/api/attendance`)
*Handles class-level attendance tracking.*
- `POST /api/attendance` - Submit/Record daily class attendance.
- `GET  /api/attendance` - Fetch attendance records.

### 6. 📢 Announcements (`/api/announcements`)
*Handles school-wide or class-level announcements.*
- `POST   /api/announcements` - Create a new announcement.
- `GET    /api/announcements` - Retrieve announcements (filtered by the user's scope).
- `DELETE /api/announcements/:id` - Delete a specific announcement.

### 7. 💬 Messages (`/api/messages`)
*Handles direct messaging and AI drafted replies.*
- `GET  /api/messages/inbox` - Retrieve the user's message inbox.
- `GET  /api/messages/thread/:userId` - Retrieve message thread with a specific user.
- `POST /api/messages/send` - Send a direct message.
- `PUT  /api/messages/:id/read` - Mark a specific message as read.
- `POST /api/messages/ai-draft` - Generate an AI draft for a message response.

### 8. 📝 Complaints (`/api/complaints`)
*Handles user complaints (e.g. bullying, infrastructure issues).*
- `POST /api/complaints/` - Create a new complaint.
- `GET  /api/complaints/my` - Get complaints submitted by the current user.
- `GET  /api/complaints/all` - Get all complaints (Admin/Management view).
- `PUT  /api/complaints/:id/assign` - Assign a complaint to a staff member for investigation.
- `PUT  /api/complaints/:id/status` - Update the status of a complaint (e.g. resolving).
- `GET  /api/complaints/:id` - Get details of a specific complaint.
